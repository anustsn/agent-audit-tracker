Agent Audit Tracker Work in progress

Which standards and drafts let an auditor answer which agent acted, on whose behalf, with which credential and tool version, and was it allowed?

Audit evidence, not monitoring. This page does not show what agents are doing. It is a research instrument that tracks the documents defining audit evidence for AI agent actions: their status and revisions, how they cite each other, and new related drafts, each with its source and the time it was checked. It does not publish research findings; those appear only as links to published work.

This version is a catalogue. It lists and links documents and reports facts from their registries. It does not assess them. The researcher's ratings of which evidence fields each document specifies will be added only after the documents have been read, and will be labelled as one researcher's reading. Rules are stated in Method, every change is recorded, and errors can be reported.

Three kinds of information are kept apart. Each section and detail is labelled. The researcher's questions and ratings are not requirements of any standard.

          How to check a fact
          1. Select a document and note its revision, the time the status was fetched and the source (IETF Datatracker or GitHub).
          2. Open the link to the registry page or the archived text; for Internet-Drafts compare the SHA-256 shown with the text you download.
          3. For a citation, open the Datatracker page of the citing draft; references are listed per revision.
          4. For the history of a fact, see Recent changes and the commit history of the data files. If something is wrong, report it as a GitHub issue.
          How to re-verify a rating
          1. Select a cell in Specification status and note the revision it was rated at and the text link.
          2. Open the archived text and compare its SHA-256 with the one shown, so you know you are reading the same bytes.
          3. Find the identifiers listed in the cell (and the location, where recorded) and read the definition.
          4. Compare with the rating and the researcher's note. If you disagree, report it as a GitHub issue.
          5. For the history of a rating, see the ratings log below and the commit history of data/fields.json.

          Method

          • Purpose. A research instrument for researchers and auditors. It does not publish findings.
          • Current version: catalogue. Only document facts are published: status, revisions, citations, related drafts and their provenance. The researcher's ratings are not published yet; the rules below describe how they will be made. Maintained by one person: rules are stated here, every change is recorded in the data history, and errors can be reported as GitHub issues.
          • Three layers. Document facts come from registries (IETF Datatracker, GitHub) or are recorded by hand with a revision and pointer (data/status.json, data/references.json, data/document_facts.json). Researcher classification covers the evidence questions, ratings, roles, document-type labels, maturity normalisation, coding links, links found by reading and the ratings log (data/fields.json, data/classification.json, data/requirements.json, data/ratings_log.json). Evidence quality is a separate assessment (data/quality.json). The files are never merged.
          • Specification status is rated only after reading, and each column records the revision that was read, the date and, where recorded, who rated it and which sections were read. "Not specified" means the document was read and does not define it; "not reviewed" means nobody has checked. When a newer revision appears, the column is marked re-check rather than silently kept. Cells are never created in advance.
          • Provenance. The update job records the archive URL and SHA-256 of each Internet-Draft text that was read and of the current revision, full commit SHAs for repositories, the source commit and workflow run of each build, and the SHA-256 of every curated data file. Every change to a rating is logged.
          • Evidence quality. Origin (as specified) and integrity of the record format. "Not established" means the research has not determined it, not that the property is absent. A specified telemetry field is not by itself reliable audit evidence. Requirement levels are document facts and are quoted as the document writes them.
          • References are taken from the Datatracker per revision: the revision that was read and the current one are listed separately, with the differences. A citation to a draft that has since been replaced is flagged; it may have been correct when written. Process references (RFC 2119, RFC 8174, BCP 14) are hidden by default and counted.
          • Revision check (automatic). For a column marked re-check, the update job compares the revision that was read with the current one and reports changed lines, added or removed section headings, and whether each recorded field identifier still appears or sits in a changed line. This only points to where to read; it does not replace reading.
          • Requirement links in the question view come from the coding in the agent-telemetry-coverage dataset (question → monitoring signal → OWASP requirement unit). Only identifiers are copied. ISO/IEC 27001 and PCI DSS are not coded yet.
          • Authority (document type) is shown for context and is never used as a weight.
          • Limits. The tracker covers the documents listed; it does not claim that nothing is missing. Internet-Drafts are work in progress. Nothing here is legal or compliance advice. Corrections are welcome as GitHub issues.

          Privacy

          • The page sets no cookies, stores nothing in your browser, contains no tracking or advertising code, and loads nothing from other servers. A content security policy tells the browser not to load scripts, styles or anything else from elsewhere and not to send data anywhere.
          • Search, filters and exports run in your browser only. Nothing you type is transmitted.
          • The page is hosted on GitHub Pages. GitHub states that when a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes (GitHub documentation). The maintainer does not receive these logs.
          • Links to other websites open without telling them which page you came from.
